# 沟通成功后保存岗位快照

## Why

用户在职位页手动点击“立即沟通”或“立即投递”后，扩展目前只会在成功弹窗中点击“留在此页”，没有保存刚刚操作的岗位。后续无法可靠回看当时的 JD、公司、薪资、HR 活跃度和沟通时间，也无法区分当时页面没有展示字段与采集失败。

## What Changes

- 在可见的“已向BOSS发送消息”成功弹窗出现时，先提取当前职位页的结构化岗位快照，再点击“留在此页”。
- 保存岗位、公司、薪资、JD、HR 和沟通成功事件；字段未展示时保存为空，并记录采集状态。
- 将这次平台确认保留为原始阶段“已沟通”，同时计作一次投递；后续“已投递”等平台文案作为同一次投递的进展阶段。
- 对可读薪资保留页面原文并解析上下限；对字体混淆的薪资保存 DOM 原始字符、码点和计算字体，并按用户确认的 `U+E031–U+E03A` 偏移规则解码，范围外码点不写入推测值。
- 同一弹窗的重复 DOM 渲染只保存一次；同一岗位未来出现新的真实成功弹窗时，允许形成新的沟通事件。
- 本地服务暂时不可用时保留待写入记录并重试，避免已经成功沟通但没有留下岗位快照。

## Capabilities

### New Capabilities

- `contact-job-snapshot`: 在用户手动建立沟通并出现平台成功弹窗后，保存当时可见的岗位、公司、薪资、JD、HR 和沟通事件。

### Modified Capabilities

- `stay-on-page`: 点击留页选项前提取岗位快照，并将留页点击结果写入沟通事件。

## Impact

- 扩展：新增纯提取模块和保存调用，修改投递页留页脚本及后台本地 API 代理。
- 服务：新增沟通快照写入接口、字段校验、幂等处理和查询能力。
- 数据库：扩充岗位属性并新增沟通事件表；继续使用 `raw_observation` 保存结构化原始观测。
- 测试：增加提取、薪资状态、成功弹窗、重复渲染、双窗口和服务重试的单元测试及接口测试。

## Out of Scope

- 不自动点击“立即沟通”“立即投递”或“继续沟通”。
- 不保存完整网页 HTML、聊天正文、头像、地图图片、手机号或微信号。
- 不通过 OCR 或猜测还原被平台字体混淆的薪资。
- 本轮不做 JD 评分、自动筛选或自动投递。
