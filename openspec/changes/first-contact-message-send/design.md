# 设计

## 入口与依赖

Manifest 向 `/web/geek/chat` 注入首次接触脚本和样式。后台保留本地 API 代理，复用 `/api/settings` 和 `/api/resume`。独立设置页只提供图片和图片后的话术；底层沿用 `advantage_message` 字段，不要求模型或 API Key。消息列表初次加载并短暂稳定后建立基线；此后列表顶部新增会话时点击对应行，待选中状态、HR、公司、职位、发送控件和消息记录均已加载后执行自动判断。列表预览和 URL 不作为必须匹配的条件，因为它们可能与会话内容异步更新。已检查的列表项在本次页面会话中不再自动重试。

投递页另注入独立的留页脚本，覆盖 `/web/geek/*` 和 `/job_detail/*`，直接在聊天页加载时退出。脚本只在可见弹窗同时包含“已向BOSS发送消息”、留页选项及“继续沟通”时点击留页选项；兼容已观察到的多种留页文案。文案嵌套在 `span` 等子节点时，脚本优先向上解析并点击实际可交互按钮；平台使用无语义 `div/span` 时，以完整弹窗三元组为安全边界，允许点击精确文案节点并利用事件冒泡。同一弹窗成功点击后不重复处理，临时校验失败不提前标记为已处理。点击前重新查找同一个可见完整弹窗；站内路由变化本身不再否决点击，因为平台可能先更新 URL 再完成导航选择弹窗，只有弹窗已经移除、重绘或不完整时才停止。两个窗口各自运行内容脚本，共用原有后台服务与本地设置。

## 判断与锚定

判断逻辑提取为无 DOM 依赖的模块，输入为当前会话的身份字段和消息摘要。自动身份由公司、HR、岗位、首条平台消息 ID 组成；手动锚点优先选择当时已有的首条消息 ID，其次选择左侧选中会话标识，最后使用 URL 会话 ID。每次副作用前重新读取所选锚点；变化即停止。图片确认只接受新增的自己发出的图片消息，文字确认只接受新增且文字匹配的自己发出的消息。

自动打开新会话后，若身份、发送控件、消息记录或首条消息 ID 尚未就绪，流程以 250 毫秒间隔等待最多 3 秒再判失败。只对“仍在加载”的原因重试；已经明确存在第二条本人消息、图片或简历系统记录时立即停止。身份读取优先使用当前会话顶部及岗位栏，兼容 `company-name`、`name-text`、`job-title` 等语义类名；公司或 HR 读不到时可从左侧当前选中会话补全，岗位仍必须来自右侧当前会话。手动按钮不要求这些身份字段，但若会话标识或对应控件尚未加载，同样等待最多 3 秒后再停止。

自动首次接触按自己发出的消息判断：只有首条打招呼文字时允许发送，对方是否回复不改变结论。旧会话即使未回复，只要自己曾发过其他内容也会拒绝自动发送。消息页面板提供整套发送、仅发图片、仅发文字三个手动入口；手动按钮是用户对当前会话的明确授权，跳过首次接触、历史尝试及公司/HR/岗位完整性判断，各自只读取所需配置并确认对应的新消息。手动会话锚点依次使用首条可识别消息 ID、左侧选中会话标识或 URL 会话 ID，因此即使顶部身份字段缺失仍可发送，但切换会话后下一步仍会停止。

完整发送在图片消息确认后再等待至少 0.5 秒；等待结束重新读取会话身份和最终消息状态。自动模式要求最终只有首条招呼与一张图片；手动完整发送要求相对上传前恰多一张自己发出的图片。图片上传期间平台可能重绘临时图片消息或更新图片 ID，因此不比较刚确认时的瞬时 DOM 与等待后的消息 ID。自动和手动完整发送均在最终状态表明切换目标或额外发送时停止话术；对方回复不导致停止。单独发送图片或文字不执行另一种发送，也不增加两者间等待。延迟用于稳定发送节奏，不作为平台风控安全阈值。

## 失败与幂等

自动发送上传前用 `chrome.storage.local` 保存按会话身份生成的尝试标记。自动发送结果不明时不重试，避免重复图片。三个手动按钮都是显式重发入口，跳过历史尝试标记、首次接触和身份完整性判断，但保留会话 ID/消息 ID 锚定、草稿保护及对应发送结果确认。标记只保存身份键和阶段，不保存聊天正文或图片内容。

## 验证

用 Node 内置 `node:test` 检查首次接触判定、发送顺序、图片未知结果、会话切换、重复启动。浏览器端控件选择器依据现有消息页样本；真实发送链路仍需在用户账号中做一次人工触发验证。
