## Purpose

用户在投递页手动发起沟通后，自动关闭发送成功弹窗并留在当前页，使另一个消息页窗口可以继续处理新会话。

## ADDED Requirements

### Requirement: 只处理发送成功后的留页选项
系统 SHALL 仅在可见弹窗同时出现“已向BOSS发送消息”、留页选项和“继续沟通”时自动点击留页选项。系统 SHALL 不点击发起沟通按钮或“继续沟通”。

#### Scenario: 用户手动发出招呼
- **GIVEN** 用户在投递页手动发出招呼
- **WHEN** 平台显示发送成功弹窗和“留在此页”按钮
- **THEN** 系统点击“留在此页”，投递页保持打开

#### Scenario: 平台使用另一种留页文案
- **GIVEN** 发送成功弹窗将留页选项显示为“留在当前页”等已知同义文案
- **WHEN** 弹窗可见
- **THEN** 系统仍点击留页选项

#### Scenario: 其他弹窗或按钮
- **GIVEN** 页面没有发送成功标题或没有“继续沟通”选项
- **WHEN** 页面出现“留在此页”字样
- **THEN** 系统不点击

#### Scenario: 留页文字嵌套在按钮内部
- **GIVEN** “留在此页”由按钮内部的文字节点展示
- **WHEN** 系统确认发送成功弹窗
- **THEN** 系统点击承载该文字的实际按钮，不点击文字节点或“继续沟通”按钮

#### Scenario: 留页选项使用无语义标签
- **GIVEN** 平台用没有 `button`、`role` 或 `tabindex` 的 `div/span` 承载留页选项
- **WHEN** 同一可见弹窗仍完整包含发送成功标题、留页选项和“继续沟通”
- **THEN** 系统通过精确文案节点触发留页选项，且不点击“继续沟通”

#### Scenario: 处理期间发生站内路由变化
- **GIVEN** 系统已经发现发送成功弹窗
- **WHEN** 岗位快照提取期间页面路径发生变化
- **THEN** 系统重新查找当前可见的完整发送成功弹窗；原弹窗仍有效时点击留页，弹窗已移除或不完整时不点击

#### Scenario: 临时校验失败后重试
- **GIVEN** 系统发现发送成功弹窗，但提取岗位快照期间弹窗发生重绘
- **WHEN** 本次点击前无法再次确认同一个完整弹窗
- **THEN** 系统不把该弹窗永久标记为已处理，并允许后续 DOM 更新时重新检查

### Requirement: 两个窗口各自执行所属流程
系统 SHALL 允许同一浏览器配置中的投递页和消息页同时打开；投递页仅处理留页弹窗，消息页继续监听新会话并执行首次接触发送。

#### Scenario: 两个窗口并行
- **GIVEN** 消息页已开始监听新会话，用户在另一窗口浏览岗位
- **WHEN** 用户手动发起沟通并选择留在投递页
- **THEN** 消息页仍可发现新增会话并执行原有判断
